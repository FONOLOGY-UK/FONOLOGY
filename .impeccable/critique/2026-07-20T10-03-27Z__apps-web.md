## Anti-Patterns Verdict

- **Deterministic scan: 0 findings, exit 0** across all 130 component/app files (admin, pos, auth, shared, ui — and the frozen storefront). No rule fired.
- **LLM assessment:** does not read as AI-generated. No card-grid sameness, no gradient text, no side-stripes, no hero-metric template. The one borderline tell: the uppercase tracked eyebrow in `PageHeader` on every admin module — defensible because the eyebrows mirror the sidebar's group names (Operations/Catalogue/Money/Team), making them a navigation echo rather than decoration, but it is the pattern at its saturation point. The bench-ticket cards, validated two-hue chart system, and till vocabulary give the surfaces a specific identity.
- Browser overlay: skipped (hidden/throttled pane) — CLI evidence only.

## What's Working

1. **One table to rule them all** — every list shares DataTable, so loading/empty/error/sort/search behave identically; consistency score is earned, not asserted.
2. **The permissions map** — tabs, routes and columns all derive from `permissions.config.ts`; the employee/manager split is one config edit, exactly as briefed.
3. **Money honesty** — integer pence domain-wide, split-payment exactness, below-cost warning with a config escape hatch, refund reasons kept on record.

## Priority Issues

- **[P1] Split-payment cash/transfer amount input fought the cursor** — controlled `value={(amount/100).toFixed(2)}` reformatted every keystroke. _Fixed this run:_ uncontrolled input keyed per portion.
- **[P1] No refund/void path for POS sales** — Returns only resolves online-order references; a counter mistake can't be reversed in-app. _Documented this run_ (NOTES.md + INTEGRATION.md: backend `createRefund` must accept sale references); a "void last sale" control is the follow-up for Tanoli to prioritise.
- **[P2] Charts had no non-visual reading** — heatmap data lived in hover tooltips only. _Partially fixed this run:_ sr-only busiest-period headline + grid marked decorative. Full data-table alternates remain a follow-up.
- **[P2] No help surface** — heuristic 10 scores 1; a single keyboard-shortcuts/help sheet (`?`) would cover the counter's needs cheaply.
- **[P3] Auth password fields lack show/hide toggles**; PIN lock has no forgot-PIN path (mock-only concern).

## Persona Red Flags

- **Alex (power user):** completes a scan-to-cash sale mouse-free until payment — the tender buttons and Complete need clicks. No bulk stock edits in Inventory. Would want F-key tenders.
- **Sam (screen reader / keyboard):** dialogs (Radix) trap focus correctly, PIN pad and steppers are labelled, chips carry text not colour alone; the charts were the main gap (partially addressed above). Board advance buttons are reachable and labelled.

## Minor Observations

- The morning float prompt fires on Sundays (shop closed per HOURS) — harmless, but a trading-day check would be truer.
- `title`-attribute tooltips don't fire on touch; the POS is desktop-fixed so acceptable.
- Discount input accepts values >100% (clamped, but the field lets you type it).

## Questions to Consider

- Should the counter get F1–F4 tender keys so a sale never needs the mouse?
- Does the owner want the below-cost warning to require a reason (like refund overrides) even while non-blocking?
- When a real card terminal lands, what happens to a sale abandoned mid-"waiting for card"?
